# Overview and history

## What it is

An isometric (viewed from above at an angle, like classic strategy games) map of
a jungle. The jungle *is* a computer network:

- **Nodes** are the machines and services: a router (📡), firewalls (🔥), a
  database (🗄️), a DNS shrine (⛩️), a load balancer on lily pads (🪷), a monitoring
  watchtower (🔭) and so on, 28 in all. Each sits on a coloured card on the map.
- **Links** are the API connections between them. Little data frames (boxes
  with a header bar) stream along every link in both directions.
- **Rivers** are data too. The main river and the *Digital River* carry floating
  frames downstream; the Digital River ends in the *Data Lake*.
- **Weather is a hazard:** storm clouds flash and can strike a node with lightning.
- **Critters** (monkeys, ghosts, bananas, lizards, crocodiles) wander for atmosphere.

The game teaches the shape of real incident response: diagnose from symptoms,
choose the right remedy, prioritise when several things break at once, and
prevent what you can see coming. See [How to play](gameplay.md).

## History

The git history tells the story; each step is one commit.

| Date | Commit | What happened |
|---|---|---|
| 2026-09-24 | `9e35d5d` | **Original export** from [v0.dev](https://v0.dev) (an AI tool that generates React/Next.js apps). A Next.js site drawing the map with DOM elements. Kept untouched as a baseline. |
| 2026-09-24 | `a10d835` | Cleaned up: v0 scaffolding stripped, hidden type errors fixed, a faster renderer using [Pixi.js](https://pixijs.com) (a 2D WebGL drawing library), moved onto the shared fridge-next container runtime. This was version 0.2. |
| 2026-10-15 | `182ece0` | **Ported to Bevy** (Rust compiled to WebAssembly). Next.js now only hosts the canvas. Fixed the tile alignment bug and the upside-down pyramid (see [Decisions](decisions.md)). |
| 2026-10-15 | `579f0f6` | First game loop (turn-based quiz), water animations, river banks, old-style clouds back. |
| 2026-10-15 | `48ca8d3` | **Game loop v2:** the walking monkey, timed fixes, TTL countdowns, Watchtower forecasts, frame streams, seven new places. |

Why the move to Bevy? The owner wanted a real game with a game loop, not a web
page. Pixi.js is a drawing library; game logic, input, state, UI and timing were
all hand-rolled in React around it. Bevy is a whole engine with those parts built
in, and its entity-component-system design (see [Engine](engine.md)) suits a
simulation with many small moving things. The cost is a large download (about
6.6 MB compressed) and long compile times.

## How the pieces fit

    browser
      │  https://go.fridge.run/luckymonkey
      ▼
    fridge-caddy (reverse proxy, TLS)
      │  /luckymonkey
      ▼
    container "luckymonkey"  (image fridge-next:14, Next.js 14, read-only)
      │  serves app/page.tsx  → a page with one <canvas id="lm-canvas">
      │  serves public/game/luckymonkey.js + luckymonkey_bg.wasm
      ▼
    browser runs the wasm: Bevy draws into the canvas with WebGL2

The Next.js page does almost nothing. It checks the browser has WebGL2, then
dynamically imports `luckymonkey.js` (generated by wasm-bindgen), which fetches
and starts `luckymonkey_bg.wasm`. From then on, everything on screen is Bevy.

## Repository layout

    luckymonkey/
    ├─ app/page.tsx          the host page (canvas + loader text)
    ├─ app/layout.tsx, globals.css   page shell, black background
    ├─ lib/world-data.ts     SOURCE of the map: nodes, rivers, terrain generators (TypeScript)
    ├─ lib/npc-data.ts       SOURCE of the critter roster
    ├─ lib/iso.ts            seeded random generator used by world-data.ts
    ├─ game/                 the Bevy game (Rust crate "luckymonkey")
    │  ├─ Cargo.toml / Cargo.lock
    │  ├─ src/main.rs        app setup, shared Art (fonts/textures), RNG, screens
    │  ├─ src/world.rs       terrain, banks, decorations, edge islands, node cards
    │  ├─ src/water.rs       waterfall streams, lagoon bubbles, glints, river frames
    │  ├─ src/npc.rs         wandering critters
    │  ├─ src/clouds.rs      clouds, rain, lightning
    │  ├─ src/view.rs        camera: pan, zoom, picking, follow
    │  ├─ src/ui.rs          welcome screen, zoom buttons, hint bar, node panel
    │  ├─ src/ops.rs         THE GAME: network model, shift, monkey, alerts, HUD
    │  └─ assets/            GENERATED inputs compiled into the wasm (see below)
    ├─ tools/export-world.cjs   lib/*.ts → game/assets/world.json + npcs.json
    ├─ tools/make-textures.py   public/sprites/*.png → game/assets/tiles.png, card*.png
    ├─ tools/deploy.sh          build on fridge + deploy
    ├─ public/sprites/       original 32 px tile sprites (inputs to make-textures)
    ├─ public/images/grid_background.png   the void's grid pattern (embedded)
    ├─ public/game/          BUILD OUTPUT (gitignored): luckymonkey.js + .wasm
    ├─ art/                  unused 1024 px illustrations from the original export
    ├─ compose.yml           the container definition
    └─ docs/                 these pages

**Generated vs source:** `game/assets/world.json`, `npcs.json`, `tiles.png`,
`card.png`, `card_border.png` are generated by the tools but *committed*, so the
Rust crate builds without Node or Python. The deploy script regenerates them
every time. If you change `lib/world-data.ts`, run `node tools/export-world.cjs`.
